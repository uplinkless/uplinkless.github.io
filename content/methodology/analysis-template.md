새 글은 번들 틀로 만든다. 글 하나가 폴더 하나다.

    hugo new content --kind analyses analyses/2026/2026-11-15-slug
    hugo new content --kind techniques techniques/2026/2026-11-15-slug

## 요약 문단

본문 첫 문단은 영어 TL;DR(2~3문장)이다. 틀에는 그 뒤에 Hugo 요약 구분자가 들어 있어서, 이 문단이 목록에서는 요약으로, 글에서는 제목 바로 아래에 보인다.

## 분석 글의 절

| 절 | 내용 |
|---|---|
| 1. English Summary | Key findings, Assessed links, Detection |
| 2. 개요 | 무엇을 왜 분석했는지, 범위, 샘플 출처 |
| 3. 트리아지 | 해시, 형식, 크기, 엔트로피, 임포트, 문자열, DIE·capa 결과 |
| 4. 정적 분석 | 구조와 핵심 함수 |
| 5. 언패킹·복호화 | 절차와 근거. 덤프한 바이너리는 올리지 않는다 |
| 6. 동적 분석 | 격리 VM에서 본 프로세스·파일·레지스트리·네트워크 시도 |
| 7. 설정 추출 | `tools/`의 추출기와 결과 |
| 8. 탐지 | 탐지 범위 표, `rules/`의 룰, 층별 검증 결과 |
| 9. IoC·ATT&CK | 표와 `iocs.csv` |
| 10. 공격 그룹 유사도 | [유사도 산정](../attribution-scoring/)의 결과 표, 근거는 `evidence/attribution.csv` |
| 11. 적대적 검증 | [적대적 검증](../adversarial-review/)의 반론 시도와 견고성 |
| 12. 맥락과 전망 | [전망 작성과 채점](../forecasting/)의 시나리오와 전망 ID |
| 13. 기관 공유 | 공유한 기관과 날짜, 공유하지 않았으면 그 이유 |
| 14. 한계와 남은 질문 | 확인하지 못한 것 |
| 15. 작업 구분과 AI 사용 내역 | 단계마다 자동(도구), AI, 직접 중 무엇으로 했는지. 직접 분석한 구간의 근거 |

## 기법 재현 글의 절

1. English Summary
2. 목적
3. 대상 프로그램(소스는 `src/`)
4. 원리
5. 재현 절차
6. 검증
7. 탐지 관점
8. 한계
9. AI 사용 내역

## 탐지 범위 표

| 층 | 형식 | 만드는 때 | 검증 |
|---|---|---|---|
| 파일 | YARA | 정적 분석에서 고유한 특징을 찾았을 때 | 정상 파일 묶음에서 검사 수와 오탐 수 |
| 엔드포인트(EDR) | Sigma, 필요하면 Elastic 쿼리로 변환 | 격리 VM에서 행위를 관찰했을 때 | 분석 VM의 Sysmon 로그에서 샘플 실행분만 걸리는지 |
| 네트워크(NDR) | Suricata, Zeek | 통신을 실제로 잡았을 때 | 캡처한 pcap에서 걸리고 정상 pcap에서 걸리지 않는지 |

근거가 없는 층은 룰을 만들지 않고 "해당 없음"과 이유를 적는다. 룰은 벤더 중립 형식만 쓴다.

## 관찰 신뢰도

- **확인**: 직접 관찰하거나 재현했다.
- **추정**: 근거는 있으나 직접 확인하지 못했다.
- **가능성**: 가설이다.

## IoC 표기

본문에서는 무력화 표기(`hxxp`, `[.]`)를 쓰고, 원래 값은 `iocs.csv`에만 둔다. 열은 `type,value,context,confidence`이고, `confidence`는 `confirmed`, `likely`, `possible` 중 하나다.

## 문체

이모지와 메타 서술("이 글에서는 ~를 알아보겠습니다" 류)은 쓰지 않는다.
